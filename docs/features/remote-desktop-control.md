## 1. 首版范围

| 角色 | v1 目标 |
|---|---|
| 电脑控制端 | Windows、macOS、Linux Desktop；优先内置 WebView 接收，Linux 的系统 WebKitGTK 路径受下述限制，接收适配仍须完成 |
| 手机控制端 | **HarmonyOS 先实现和真机验证**，Android、iOS 后续接入；共享窄的 WebRTC 媒体接收模块，外层保持原生界面 |
| 被控端 | Windows、macOS、Linux Desktop；已登录并解锁的图形会话 |
| 暂不支持的被控端 | HarmonyOS PC、手机、CLI、SSH/容器和 Detached Dispatch host |

本轮不新增 mobile-web 远程桌面功能，聚焦原生手机 App 与 Desktop；现有浏览器会话控制保持原有范围。

这些是目标平台，不是已验证支持。没有可用 provider 或 WebView 接收能力时明确禁用；不能用浏览器模拟手机替代真机证据。仓库本地 `src/apps/ohos/` 构建产物不能作为鸿蒙 PC 被控能力的证明。

Linux 原生 API 探针已确认 WebKitGTK 2.54 无 WebRTC，显式开启设置也不恢复；该版本不能承诺通过内置 WebView 接收。Linux 已接入独立原生 libwebrtc 解码与二进制帧沙箱绘制适配，不依赖 WebKitGTK 内置 WebRTC；尚未验证实际 Linux WebView 和整包。手机和其他平台保持现有接收路径。证据与限制见[协议与媒体 §7.2](../architecture/remote-desktop-control.md#72-共享接收与平台例外)。

首版每台被控电脑同时只允许 **一个 attachment、一个选定显示器、一条视频轨道**。同一 attachment 可在仅查看和操作之间切换；第二个连接者看到“该电脑正在被另一设备使用”，不能抢占。多显示器支持逐个切换，不同时拼接。

必须完成画面、基础键鼠/拖动/滚轮、按能力开放的文字输入、按设备授权、停止、重连和切屏。多观察者、跨设备抢占、AI 自动让权、AI Background 并发、音频、剪贴板同步、文件传输、录制、虚拟屏、远程重启、开机登录及 UAC/安全桌面留待后续能力设计。

## 2. 设备发现与授权

鸿蒙入口位于侧栏，与“小应用”并列：**远程控制 → 选择在线电脑 → 打开桌面**。专用设备选择页只调用远控入口，不切换 Agent 会话或工作区；普通设备列表不再提供额外的“查看桌面”按钮。

自部署服务只接受独立配对，不复用登录 Relay 的用户、token 或设备列表。电脑入口位于设备与连接中的“自部署远程桌面”；鸿蒙入口提供服务地址与配对密钥。配对密钥仅用于登记设备，不保存到客户端；设备访问凭据及私钥单独加密保存。凭据过期可用原设备密钥重新配对，换钥仍须本机重新授权。设备目录按 kind 选择 Desktop，再协商真实媒体能力；CLI 和其他没有 provider 的目标明确不支持。

被控电脑默认关闭远程桌面。本机设置分别管理可查看的显示器、可信控制设备以及每台设备的“查看”“操作”权限。**同一远控服务中的配对仅允许发现和申请，不自动获得画面或操作权。** 首次请求在电脑本机确认，可选仅本次或记住该设备；查看权限也默认按设备授权，首版不开放“所有新登录设备自动查看”。

用户也可以出门前在被控电脑设置中，从远控服务的配对设备列表选择手机/电脑并提前授权，固定该设备指纹和允许范围，无需等待远端发起请求。首次信任依赖受信 Relay 分发公钥；具体威胁模型见协议文档。

当前本机入口已支持分别保存“仅查看”和“查看并操作”预授权；旧的查看记录不会自动获得操作权。保存操作授权不会启动共享或自动接管电脑；启用原生媒体的构建在系统许可、媒体健康和 GUI 互斥均满足后，才允许显式申请操作。授权确认要求先停止 AI / 远控操作；重新确认仅查看会清除该设备此前保存的操作范围。

许可绑定配置的远控服务、稳定设备 ID 与设备公钥指纹，名称仅用于展示。不同服务的授权文件分别保存，密钥变化、设备重装或新注册都重新确认。既有许可不能通过账号同步或新电脑恢复自动变成这台被控电脑的信任；本机撤销立即停止相应流和输入。

这个首次设备信任确认只能由被控电脑的本地设置/确认入口完成，不能通过新设备自己的远程请求、Peer proxy 或通用 permission-mailbox 自批。控制端显示“等待电脑端确认”，本机不在场时不能完成首次授权。后续已信任设备在 OS 许可仍有效时可免去重复的产品确认；OS 弹窗是否需要本机操作另行显示。

本机持续显示连接设备、共享屏幕、仅查看/操作状态，并提供“停止操作”“结束共享”“撤销该设备”。手动停止不会被自动重试重新打开。

## 3. 电脑端交互

独立远控服务的设备列表提供“远程桌面”入口。点击后打开“远程桌面 · 设备名”主内容标签；`sceneStore` 管标签，`contentResourceStore` 管资源，资源归控制端本地的无工作区 scope，key 包含服务标识、连接代次和目标设备。重复打开聚焦原标签，不调用 `activatePeer`。

顶部显示设备、连接状态、显示器、画质、适应窗口/原尺寸和全屏；底部显示“仅查看 / 由你控制 / AI 正在占用”，以及开启/释放操作和断开。全屏只改变本地呈现。

当前入口已接入主内容标签，提供“适配窗口 / 原始尺寸（100%）”。原始尺寸按当前接收帧的像素宽高显示为本地 CSS 尺寸，不修改电脑分辨率；大画面通过本地滚动查看，网络自适应改变接收尺寸时同步调整。更改比例或滚动画布先结束操作，媒体连接保持，用户重新开启操作后才发送新输入；新连接默认适配窗口。电脑支持画质预设时，暂停页提供省流、均衡、清晰选择；设置确认后保持暂停，需点“继续查看”取得新画面并重新申请操作。暂停前如本页处于全屏，先退出以显示画质菜单。旧版电脑隐藏选择器；三档实际画面与带宽仍待验收。已支持的电脑可通过“暂停共享 → 切换显示器”刷新允许查看的目录，以序号和尺寸区分并标记当前项；取消留在暂停页。确认选择后保留 attachment，重建媒体、等待新首帧，只恢复查看；需要操作时重新开启。也可以不换屏，直接“继续查看”。旧版电脑未声明 source_lifecycle_v1 时隐藏这些入口。

支持元素全屏的窗口可将整个远控页全屏，保留目标设备名、工具栏、退出全屏和断开入口；画布使用剩余空间，原始尺寸仍可滚动。进入 / 退出先结束操作，过渡期间不能开启操作，不重建媒体；Esc 在本地退出全屏，之后须重新开启操作。打开显示器选择前先退出本页全屏，让设计系统的选屏菜单可见。隐藏、关闭、远控凭据失效或连接结束退出本页申请的全屏；在途申请迟到成功也立即退出，不占用或关闭其他页面的全屏。不支持或申请失败时保留窗口内查看，并给出不可用状态。

仅当当前连接已呈现首帧、画面可见且健康、页面有焦点并持有有效输入租约时发送键鼠。健康检测方式由媒体探针确定，不把静态桌面没有持续出帧直接判成故障。黑边和工具栏不产生远端坐标；打开菜单或窗口失焦释放已按下的键/按钮，标签隐藏释放租约。重新聚焦先同步状态，不补发旧输入。

远控标签属于控制端，切换 Peer surface 时保留在主标签栏，和各设备的文件标签分别管理；默认不替用户激活远控页。隐藏已呈现的页面时停止输入并按 source_lifecycle_v1 暂停媒体；返回且保留期仍有效时重建仅查看连接，不恢复租约或文字草稿。手动暂停仍保持暂停；不支持暂停、协商尚未完成或保留期已结束时显示显式重连，重新选择显示器后才创建新 attachment。新连接对支持 source 生命周期的电脑先等本设备原有共享及清理结束，再展示新目录；等待可取消且有上限，不接管或恢复旧操作权，其他设备占用时明确拒绝。关闭页在既有 close guard 内立即退役输入 / 媒体，再等待标签导航完成和移除，不以 React 卸载作为唯一停止条件；断开不取消远端 Agent 的文件/终端工作。

应用可捕获的普通组合键发送到远端；本地退出全屏和停止入口始终可达。快捷键面板只开放目标实际支持的动作，不承诺拦截 OS 保留组合键或发送安全注意序列。

## 4. 手机端交互

手机首条交付路径是 **鸿蒙手机 → OpenBitFun Desktop**。先用现成浏览器发送端验证鸿蒙 App 内 ArkWeb 能显示电脑画面及使用 TURN，再做 macOS 原生显示器 source；接入设备授权后形成只读闭环，最后增加操作、手势和键盘。探针与只读阶段均不开放 OS 输入。Android、iOS 不作为鸿蒙首轮试用的前置依赖；电脑控制电脑仍在 v1 范围内。

鸿蒙在电脑声明支持画质预设时，于“更多 → 暂停共享”页面显示当前画质及省流、均衡、清晰三档。暂停完成后才可选择，当前档位不可重复点击；设置确认后继续保持暂停，由用户点“继续查看”建立新画面连接，操作权需重新申请。旧版电脑隐藏选择器。该入口已接线，真实三档画面 / 带宽及其他控制端的画质选择仍待验收。

设备列表进入远程桌面，无需选工作区。以深色媒体画布衬托电脑画面，顶部是关闭、居中的设备胶囊和更多菜单；底部显示操作状态并保留键盘按钮。鸿蒙连接取得新首帧和正常传输状态后，自动通过原有授权流程申请操作，无需点“开启操作”；停止和异常后的“恢复操作”放在更多菜单。明确停止、拒绝、撤销或信令中断后不自动重试；正常媒体凭据更新仅在用户仍希望操作时申请新租约。模式、移动画面、旋转屏幕和断开放进锚定“更多”的菜单；横屏键盘展开时菜单限高并可滚动。键盘升起后，操作状态、收起键盘和可横向滑动的特殊按键胶囊共用一行，贴在键盘上方；极矮的横屏窗口还将更多入口并入该行。紧凑、宽屏和折叠屏保持相同操作含义，键盘弹出后工具栏仍可达。手动旋转只切换手机视口，先关闭键盘、释放操作权，不旋转电脑显示器；退出远控恢复原窗口方向策略。旋转和折叠保留逻辑 attachment、取消当前手势并重算坐标，不创建 Agent session。

| 操作 | 鼠标模式 | 直接触控模式（默认） |
|---|---|---|
| 单指移动 | 移动虚拟指针 | 无拖动手势时不发送鼠标 down |
| 单击 / 双击 | 在指针位置点击 | 在触点点击 |
| 右键 | 长按或工具栏按钮 | 长按触点；移动超阈值取消 |
| 拖动 | 双击第二次按住后拖动，另有拖动锁定 | 双击第二次按住后拖动 |
| 双指平行滑动 | 放大后平移本地画布；适配尺寸时为远端滚轮 | 相同 |
| 双指捏合 | 本地缩放 | 本地缩放 |
| 移动画布 | 开启“移动画面”工具，仅将该手势用于本地平移，保留操作权；结束后直接点击电脑 | 相同 |

本地缩放、平移与触摸取消只清理当前手势、松开已按下的鼠标，不切换为仅查看，也不重新申请操作权。手势判定后锁定类型，判定前不发送不可撤销的点击/滚轮。键盘、安全区、黑边不计入远端内容区。工具栏、手势识别、无障碍和键盘保持各平台原生实现；共享 Web 模块仅处理视频/DataChannel，不扩成共享 App UI。

鸿蒙右下角在键盘旁提供“截图”：截取当前显示器的完整接收视频帧，不受本机缩放、平移影响，不含手机工具栏。截图与键盘为右下角同尺寸并排图标；点击打开紧凑的底部图片预览面板，可通过系统保存控件保存到手机相册；关闭预览清理临时文件。图片分辨率跟随当前接收视频，不另发原生全分辨率捕获请求，也不通过远控信令服务上传图片。仅查看时也可截图；首帧尚未出现、连接中断或目标已切换时明确失败，不保存旧画面。

手机使用**手机原生输入法**：先点击电脑画面中的输入框，再点常驻键盘按钮，中英文统一使用手机输入法，确认的文字直接进入远端当前焦点。输入法上方保留紧凑的退格、回车、Esc、Tab 和方向键工具条，不维护独立的电脑字母键盘和输入模式切换。输入不经过本地草稿或额外“发送文字”按钮，不读取或镜像远端输入框内容。中文 composing 留在本机，输入法确认候选词才发送一次 `text_commit`，取消、退出或租约变化丢弃未确认的组合，不猜测或重放。

退格、Delete、Enter、Tab、Esc、方向键与修饰键按目标支持的物理键单独发送，不能把手机本地编辑状态的差分当成远端全文修改。没有远端文本上下文时，输入法的批量删除/范围选择须明确拒绝，不能把 UTF-16 长度猜成等量退格。目标未声明文本能力时明确禁用键盘文字输入，不偷偷改剪贴板。外接键鼠遵守相同焦点规则。

后台、锁屏或离开页面释放操作并暂停媒体；前台不自动恢复连接。只在可见远控页保持屏幕常亮。受控 WebView 只装载随 App 打包的媒体页，不给外部网页暴露原生桥。

当前鸿蒙实现会在后台结束本次连接，返回后显示“已断开”和“重连”。用户点重连后重新读取设备目录与能力、选择显示器，取得新帧与正常传输状态后重新申请操作；远控服务或设备身份改变时需返回配对设备列表重新选择。支持 `source_lifecycle_v1` 的电脑另提供“更多 → 暂停共享”：先停止手机输入，待电脑确认暂停与清理后显示“继续查看”。继续时保留 attachment、建立新的媒体连接，收到新首帧与正常传输状态后重新申请操作，通过后启用输入和键盘。电脑未声明能力时不显示此入口，暂停保留期结束后走显式重连。它与后台结束连接的行为分开，不把重连当作恢复旧 attachment。 支持 source 生命周期的电脑在新连接准备时，手机先等待原有共享及清理结束，再提供显示器选择；等待有上限、可退出，不接管旧操作权。其他控制设备占用时明确提示忙碌。 暂停页可点“切换显示器”，重新读取电脑当前允许查看的显示器；以序号和尺寸区分、标明当前项。选中后以同一 attachment 执行 select_display，再建立新媒体、等待新首帧；取消则留在暂停页，不自动恢复。目录过期、目标消失或选择被拒绝时明确结束，不自动改选旧屏幕。

## 5. 与 AI 及本机操作的关系

v1 人工远控和 AI GUI 输入互斥，包括 Background 模式。Background 不移动全局光标也可能修改人工正在读取/编辑的应用内容；在没有窗口级资源隔离和目标重叠规则前，不宣称两者可安全并存。

现有 Admission 不支持抢占。AI 持有控制会话时，远控申请返回 `control_busy`；即使当前无工具动作，也需原 owner 通过现有停止路径释放并完成清理。用户通过已有任务界面完成停止后再申请；不新增“点一下远控就取消 AI”的隐藏动作。人工持有 GUI reservation 时，新 AI GUI 调用保持明确的占用错误，不自动抢回，也不阻塞无关文件/终端工作。

v1 只新增外部 reservation，不把人工连接或显示器塞进 AI 的 owner/target 模型；该互斥改动仍需覆盖隐式 Background 准入与原生清理的专项验证。

未来若提供人工接管 AI，须单独评审“取消当前动作 → 失效旧 token → 原生清理完成 → 转交 owner”的状态转换和 Runtime 恢复语义，补等价测试。后台与前台并发属于另一个行为边界，不随接管一起隐式开启。

本机用户可使用键鼠，也可随时停止共享；v1 不屏蔽本机输入。仅查看不获得 GUI 输入 reservation，但独立观察 source 的资源和权限仍须验收。

## 6. 断线与平台提示

被控电脑检测到自身 Relay 失联、绑定的控制连接失联或身份未知时立即撤销操作权；手机自身短暂断开 Relay 不单独撤销 host 租约，但后台、失焦、媒体故障和用户退出仍在本地停输入。普通失联允许已授权视频最多保留 30 秒，页面显示“连接验证中，暂不可操作”。宽限从首次检测到问题开始，失败重连不能重置；完整停止延迟还包含故障检测时间，必须实测。超时停流，重新核实身份后仅恢复观察，操作需用户重新开启。

当前鸿蒙和电脑查看页对已呈现画面的暂时性状态读取失败提供有界等待：立即停止本地操作并尽力释放租约，显示信令中断提示，禁止重新开启操作和暂停 / 切屏；视频保持原连接，断开入口始终可用。首次读取失败后最多等待 30 秒，后续失败不延长；恢复须核对同一身份、attachment、连接和显示器仍在 streaming，之后只恢复查看。账号 / 密钥 / 原生 context 变化、明确授权拒绝、媒体失败及后台 / 隐藏不走此等待。尚未呈现的连接和在途 mutation 失败继续按原路径结束，不重放申请；这也不代表 Relay 重启后的身份重绑定已经通过验收。

本机停止/撤销、锁屏、OS 权限撤销，以及被控电脑收到独立服务明确授权失效通知时，立即停输入和画面，无额外宽限。同设备重新配对并显示在线不能延续旧连接的授权。复用现有鉴权和 presence，补连接失效通知而不新增周期查询；通知未送达时通过连接关闭/超时兜底。远控与登录聊天各持独立连接，退出登录不会关闭远控，断开远控不会关闭聊天。

| 平台 | 产品必须如实显示的限制 |
|---|---|
| Linux Wayland | 首次 portal 选择需本机操作；只有后端支持并接受持久化恢复时才可能免重复选择。restore token 失效/撤销后重新确认，不能承诺永久无人值守 |
| Linux 文字输入 | 仓库已有 Unicode keysym 路径；实际中文/emoji 到达依赖 compositor、键盘布局与目标应用。未通过的组合不开放 `text_commit` |
| macOS | 录屏、辅助功能权限及系统可能要求的再次确认需本机处理；按实际 OS/API 验证，不能承诺永久免提示，也不硬编码“macOS 15 所有捕获每月确认” |
| Windows | 限当前用户解锁会话，安全桌面/UAC/登录界面明确不支持 |

系统重新授权可能中断已信任设备的访问。产品应区分设备信任缺失、OS 权限缺失、AI 占用、媒体失败与网络恢复，提供针对性的下一步，而非统一显示连接失败。

## 7. 交付边界

顺序为：**鸿蒙 ArkWeb 接收探针 → macOS 原生发送 → 鸿蒙授权只读 → reservation 与输入 → 电脑控制端及其他平台**。Linux 实际 WebKitGTK 接收能力也尽早探测，失败只阻塞 Linux 对应入口。只读探针须本机测试人员明确授权选定屏幕；浏览器 getDisplayMedia 属于浏览器捕获，生成的图案才属于合成帧，两者都不能替代后续原生 source 和实际输入验收。

所有验收项和阶段完成标准统一见 [协议与媒体第 9 节](../architecture/remote-desktop-control.md#9-实施与唯一验收矩阵)。本文不维护第二份矩阵。
